# Guidon Rebrand — Plan 1b: Unified Sidebar, Onboarding, React Bits

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the app's two separate navigation layouts (a horizontal top bar on global pages, a left sidebar only inside a project) with one persistent, collapsible left sidebar everywhere; give a brand-new user (0 projects) an onboarding view instead of a dead-end empty dashboard; add two React Bits components used sparingly; close the two remaining color-system gaps.

**Architecture:** Install shadcn's official `sidebar` primitive (collapsed-state cookie, mobile responsiveness, active-item styling built in) and wrap it with Guidon-specific nav data in a new `AppSidebar` client component, driven by a new `AppShell` server component that reads the persistence cookie. Every page that currently renders `<Navigation>` or is wrapped by `<ProjectSidebar>` swaps to `<AppShell>` instead — same file, same route, only the layout wrapper changes. `admin/layout.tsx` (which already wraps all 5 admin pages in one shared layout) gets the swap once, not per-page.

**Tech Stack:** shadcn `sidebar`/`sheet`/`tooltip`/`separator` primitives (Radix UI underneath), `next/headers` cookies for SSR-safe collapsed state, React Bits (`@react-bits/*` via the shadcn CLI).

Spec: `docs/superpowers/specs/2026-08-22-guidon-rebrand-design.md` (see "Phase 1 addendum" section)

**Precondition:** Plan 1a must be complete and merged first — this plan's `Button`/`Input`/`Card` shape assumptions (flat, `--radius` token, no shadow) depend on it, and the shadcn `sidebar` install (Task 1) will try to overwrite `button.tsx`/`input.tsx` with shadcn's stock (rounded, shadowed) versions, which Task 1 explicitly declines.

### Task 3: `AppShell` — server wrapper with cookie-backed collapsed state

**Files:**

- [ ] **Step 1: Write the component**

Create `src/components/layout/app-shell.tsx`:

```typescript
import { cookies } from "next/headers";
import { SidebarInset, SidebarProvider, SidebarTrigger } from "@/components/ui/sidebar";
import { Separator } from "@/components/ui/separator";
import { AppSidebar, type AppSidebarProps } from "@/components/layout/app-sidebar";

type AppShellProps = AppSidebarProps & { children: React.ReactNode };

/**
 * Reads the sidebar's own persistence cookie server-side so the first paint
 * already matches the user's last collapsed/expanded choice — the shadcn
 * sidebar primitive writes this cookie client-side on every toggle
 * (src/components/ui/sidebar.tsx's SIDEBAR_COOKIE_NAME), this just reads it
 * back before rendering instead of always defaulting to expanded.
 */
export async function AppShell({ children, ...sidebarProps }: AppShellProps) {
  const cookieStore = await cookies();
  const defaultOpen = cookieStore.get("sidebar_state")?.value !== "false";

  return (
    <SidebarProvider defaultOpen={defaultOpen}>
      <AppSidebar {...sidebarProps} />
      <SidebarInset>
        <header className="flex h-12 shrink-0 items-center gap-2 border-b border-border px-4">
          <SidebarTrigger />
          <Separator orientation="vertical" className="h-4" />
        </header>
        {children}
      </SidebarInset>
    </SidebarProvider>
  );
}
```
