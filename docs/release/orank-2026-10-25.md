## Web Bot Auth deployment handoff

1. In a private local directory, run
   `node scripts/create-web-bot-auth-key.mjs .env.web-bot-auth.private.jwk`.
   It generates an Ed25519 key, starts validity immediately, expires after one
   year, creates a new file exclusively and never prints the secret value.
   The suggested `.env*` filename is ignored by Git. On Windows, verify the
   directory ACL; a POSIX mode does not establish Windows access control.
2. Store the file's complete JSON as the hosting secret
   `WEB_BOT_AUTH_PRIVATE_KEY`. Do not use a `NEXT_PUBLIC_` variable, commit the
   file, paste it in chat or include it in screenshots. No live key is included
   in this PR. Remove the local copy securely after storing it.
3. Deploy only with approval. Verify the HTTPS key directory returns active
   public Ed25519 JWKs and signed headers with no `d`, and run the checker above.
   The directory is the outgoing-signature identity of this Guidon server; it
   is not a generic authentication bypass for incoming agents.
4. Record key expiry and rotate ahead of it. This code fails closed outside
   the validity window; the directory cache can live for 24 hours. Plan rollover
   and receiver cache refresh before switching keys; automated overlapping-key
   rotation is not implemented here.
