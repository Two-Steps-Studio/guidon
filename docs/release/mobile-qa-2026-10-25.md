# Mobile QA — 2026-10-25

Guidon card: `c011cbbb-bc9a-47db-b810-6e4f116ea078`.
Base: `77c4611`, after merged PR #73. This is functional mobile QA, not a
new security-audit certification or a production deployment.

## Changes

- Mobile sidebar navigation explicitly closes the drawer after ordinary
  internal links. Project views share a layout, so changing routes does not
  automatically unmount it. Modified/new-tab/download links and dropdown
  controls keep their existing behavior. The mobile drawer also exposes its
  existing translated Close button.
- The board title/project summary occupies its own row on narrow screens.
  Previously the sort/import controls squeezed the heading into multiple lines
  and made the summary excessively tall. Long names wrap inside the available
  width; desktop controls retain their flexible layout.
- Touch/pen dropdown triggers use a stationary pointer release instead of
  relying on a compatibility click after a cancelled pointerdown. WebKit
  emulation exposed a priority picker that did not open. Movement over 10px
  or pointer cancellation discards the pending tap. Mouse/keyboard remain on
  Radix's normal handlers. No forced clicks, user-agent application branching,
  disabled zoom or increased test timeouts are used to pass the tests.

## Automated matrix

`node tests/e2e/run.mjs --mobile-audit` builds a clean source copy and creates a
disposable PostgreSQL database, fake accounts and local HTTPS app. It uses the
existing runner's request/environment guards and retains video/traces on
failure. The separate `mobile` CI job runs the same command and uploads its
evidence. No paid provider or Cloud project is required.

For Chromium, Firefox and WebKit, at widths 375/390/430 and height 812:

- Open/close sidebar with touch and navigate Calendar → Task Board within the
  same project layout, checking that the drawer actually closes.
- Check document width, horizontal board scrolling and an unsqueezed title.
- Create a task, fill its description, select an image and submit with a
  reachable, unobstructed button. Check the actual task/attachment rows.
- Reload, open the task, choose High priority with touch, save, reload and
  verify persisted data. Move to Review through the touch menu and reload.
- Check at least 16px computed text on editing fields and visible hit targets;
  preserve user zoom. Capture a screenshot for each portrait width.
- At 812×375 landscape, reach and use the task form's Cancel action.

Chromium additionally uses real CDP touch events to check short-swipe native
board scrolling without a mutation, long-hold cancellation without a mutation,
and a long-hold drag to the neighboring column with a persisted status change.
This is browser input emulation; it is not evidence of behavior on physical
Android hardware. WebKit uses an iPhone user agent/mobile viewport, Chromium
uses an Android profile, and Firefox provides supplemental coarse-pointer
coverage without claiming native iPhone/Android engine parity.

Final run IDs/results are appended after verification. Failed exploratory runs
are not reported as passes. Inert drag artwork can duplicate task IDs outside
the board; the test targets the actual board cards rather than decorative ghosts.

## Manual device handoff — remains open

On a real iPhone in Safari and a real Android phone in Chrome:

1. Record model, OS/browser version, URL and tested commit/deployment.
2. Rotate portrait/landscape and expand/collapse browser chrome. Check header,
   dialog actions and close buttons near safe areas.
3. Open the software keyboard in login/new task/task edit/chat; confirm the
   focused input and actions remain reachable without unintended zoom.
4. Scroll vertically and swipe the board horizontally. Short swipes must not
   move tasks; hold then drag must move once; an interrupted hold must not save.
5. Navigate using the drawer and repeat touch dropdown open/close/select.
   Check there is no persistent hover or native selection/callout interference.
6. Choose an image from Photos/Files, create and edit a task, then refresh to
   verify text, priority and attachment persistence. Cancel a dirty edit and
   check that the confirmation preserves the typed text when cancelled.

Do not mark the full card Done from browser emulation alone. The mobile-native
skill explicitly requires “Test on hardware before calling it done.”
The owner can perform this checklist on test data when a suitable test URL is
available; it does not require creating another Supabase Cloud project.
